## Lecture

We've assembled our resource directory from components and worked on its appearance. Let's try using it. We can type into Search and check Open now, but the rest of the interface doesn't know what we've done. The category buttons don't remember a selection either.

In this lesson, we'll give our components that memory. We'll use **state** to keep track of input and **event handlers** to update it. Our first goal is deliberately small: make the controls respond and show what they remember. Connecting Filters to Results comes in Lesson 13.

### Learning Outcome Guide

*At the end of this class, you should be able to...*

- Attach click, change, and submit handlers through JSX.
- Use `useState` to retain a string, an array, and a boolean between renders.
- Control text inputs with `value` and checkboxes with `checked`.
- Calculate a new array from previous state without modifying the old array.
- Explain which component owns a piece of local state.

### Target behaviour

| Interaction | What we should see |
| --- | --- |
| Type into Search | A preview repeats the current search term |
| Select a category | Its button shows that it is selected |
| Select that category again | Its highlight disappears |
| Choose All | The category selection becomes empty |
| Check Open now | A preview changes from No to Yes |
| Submit the form | The browser logs the current values without reloading |

### Remembering information between renders

A normal local variable is created again each time React calls our component. `useState` gives us a value that React remembers and a function that requests an update:

```js
const [searchTerm, setSearchTerm] = useState('');
```

We read `searchTerm` while rendering. An event handler calls `setSearchTerm` with the next value. React then renders with that value. Calling the setter doesn't change the variable in the handler that's already running. See React's [`useState` reference](https://react.dev/reference/react/useState).

Call hooks at the top level of a component or custom hook, before any conditional returns. Don't put a `useState` call inside a click handler, loop, or `if` statement.

### Let state describe the interface

An uncontrolled input already lets us type. A **controlled input** also makes its current value available to our React code. We supply `value` and an `onChange` handler; for a checkbox, we supply `checked` and read `event.target.checked`. React's [input reference](https://react.dev/reference/react-dom/components/input#controlling-an-input-with-a-state-variable) compares the two approaches.

We don't need to query the DOM or change classes ourselves. JSX describes what the interface should look like for the current state.
