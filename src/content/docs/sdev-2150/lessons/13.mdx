## Lecture

In Lesson 12, Filters remembered our choices and Results remembered a selected resource. Each component could respond to its own events. Now we want those choices to affect other components: a search should change Results, and selecting a result should change Details.

Let's look at the component that brings those pieces together. `App` already renders Filters, Results, and Details. It can own the information they share and pass each child what it needs. Moving state to that common parent is called **lifting state up**.

### Learning Outcome Guide

*At the end of this class, you should be able to...*

- Identify the nearest common parent for components that need shared state.
- Move state to that parent and pass values and callbacks through props.
- Derive a filtered list from existing data and state.
- Render a useful message when there is no selection or no matching result.
- Keep local form feedback separate from shared application state.

### Agree on the component contract

| Component | Receives | Reports through a callback |
| --- | --- | --- |
| Filters | Search text, selected categories, Open now | Changes to those filter values |
| Results | Filter values and the selected resource | The resource the user selects |
| Details | The selected resource | Nothing for this activity |

`App` will be the **single source of truth** for the shared values. Children render the values passed down to them and call the callbacks passed down to them. Calling a callback doesn't bubble a custom DOM event; it's an ordinary function call.

This follows the same communication goal as our Web Components work in Lesson 03: the result item doesn't need to find the details panel. The parent connects them. React's [sharing state guide](https://react.dev/learn/sharing-state-between-components) explains this pattern.

### Store the choices; calculate the result

The search text is state. The array of resources that match that text can be calculated during rendering. Keeping another state variable for the filtered array would give us two values to keep synchronized.

For our directory, filters will apply as soon as their values change. An empty category array means All, and category names will keep the same capitalization as the source data. Our form submission will demonstrate validation separately; it won't be required to refresh the results.

### What we've accomplished

Trace a title click from the button to `onSelectResource`, through `App`'s setter, and back down to Details. Then trace a search change through the same pattern. There is one owner for each shared value.

Passing props through many intermediate components is often called **prop drilling**. Our composition only needs a few explicit connections. We'll consider other patterns when the application needs them.
