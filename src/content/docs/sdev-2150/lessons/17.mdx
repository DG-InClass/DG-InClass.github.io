## Lecture

Our resource directory now loads data and remembers a selection. Let's give the application a second screen for managing those resources. We want a URL for each screen, navigation between them, and a header that stays in place.

We'll use **React Router 7** in its declarative mode. The routes will have fixed paths: `/` for the directory and `/admin` for management. Here, *static routing* means those fixed path patterns; the pages can still fetch and change data.

### Learning Outcome Guide

*At the end of this class, you should be able to...*

- Configure `BrowserRouter`, `Routes`, and `Route` for fixed client-side paths.
- Move existing functionality into a page component without losing its behaviour.
- Use a layout route and `Outlet` to share the header and page layout.
- Use `NavLink` to navigate and identify the active page.
- Build a basic create-resource form with pending, success, and error feedback.

### Plan the responsibilities

| File | Responsibility after the refactor |
| --- | --- |
| `main.jsx` | Defines the router and route tree |
| `App.jsx` | Renders the shared layout and an `Outlet` |
| `Header.jsx` | Contains navigation to both pages |
| `ResourceDirectoryPage.jsx` | Owns directory filters, selection, fetching, and composition |
| `AdminPage.jsx` | Loads the management list and handles the create form |
| `PageLayout.jsx` | Continues to supply the responsive grid |

The nested route's element appears where App renders `Outlet`. The index route supplies the default child at `/`. React Router's [routing guide](https://reactrouter.com/start/declarative/routing) shows this relationship.

Our resource ids will still be used in API requests, but we won't introduce route parameters, loaders, or actions in this lesson.

### What navigation preserves

The shared layout stays mounted when we move between its child routes. The page component being left is removed, and the page being entered mounts. Returning to the directory creates fresh filter state and fetches the list again. Selection can be restored from `sessionStorage` through our custom hook.

Calling `useResources` in both pages gives each page its own request state. The hook doesn't create a shared cache.

### What we've accomplished

We've separated page responsibilities while keeping a shared header and layout. The router chooses a page; each page owns its relevant state and requests. The guided activity supports listing and creating resources. Updating an existing resource is the next independent challenge.

An Admin route is a page organization choice here. This classroom backend has no authentication or authorization; naming a path `/admin` doesn't restrict access.

## Practice

### Complete the management page

Extend the resource directory's Admin page using the existing backend contract:

- Add controlled inputs for category, summary, location, hours, contact, Virtual options, and Open now. Use `checked` for boolean fields, and keep labels connected to their inputs.
- Let a user choose an existing resource with a keyboard-accessible Edit button. Populate the form and track `editingId`, using `null` for create mode.
- Submit new resources with `POST /resources`; update an existing resource with `PUT /resources/:id`, encoding the id in the URL. PUT requires the complete set of fields and must retain the existing id.
- Make create and edit modes clear through headings or button labels. Add Cancel editing to clear the id, form, and old feedback.
- Retain the entered values on failure, disable submission while saving, and refresh the list after success.

Check that editing changes one existing record instead of adding a duplicate. Confirm that Cancel returns to create mode. If you edit the currently selected resource, revisit the saved-snapshot limitation from Lesson 16 and decide how to refresh those details.

As a routing extension, add a `*` fallback route inside the shared layout that shows a helpful not-found message and a link to Directory.
