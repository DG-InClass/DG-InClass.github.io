## Lecture

In Lesson 10, we used Tailwind utilities to decide how our resource finder should adapt to different screen sizes. We also kept the layout rules separate from the components displaying the content.

Let's look inside those components now. Our buttons repeat classes for borders, padding, colours, and hover styles. What if we could give a button a shared appearance with a class such as `btn`, then describe its purpose with `btn-primary`?

In this lesson, we'll add **DaisyUI 5** to our existing **Tailwind CSS 4** setup. We'll update the shared card and the buttons in Resource Details, then explore how themes affect their appearance.

### Learning Outcome Guide

*At the end of this class, you should be able to...*

- Install and configure DaisyUI in a React project that uses Tailwind 4.
- Apply DaisyUI component classes to existing JSX.
- Enable built-in themes and apply one with `data-theme`.
- Distinguish fixed colour utilities from theme-based colour roles.
- Preserve responsive layout and semantic HTML while refactoring styles.
- Explain one benefit and one trade-off of using a component library.

#### Target behaviour

- The page keeps its stacked, medium, and large-screen arrangements.
- All three cards share the updated appearance through our `Card` component.
- The existing Details buttons use DaisyUI styles.
- Changing the selected theme changes the page surfaces and the refactored components.

We're working on appearance. The starter's buttons do not yet copy an email address, open a map, or filter the results. Adding CSS classes won't implement those actions.

#### Two meanings of “component”

We've been writing **React components**: functions such as `Card` that return JSX and accept props.

DaisyUI provides **CSS component classes**, such as `card` and `btn`, that we apply to HTML elements. We can use those classes inside our React components. We don't need to import a DaisyUI React `Button` to style a `<button>`.

```jsx
<button type="button" className="btn btn-primary">
  Open map
</button>
```

Here, `btn` supplies the button styling and `btn-primary` selects its primary colour treatment. We still choose the HTML element, its text, its type, and any behaviour. See the [DaisyUI button reference](https://daisyui.com/components/button/).

#### Layout, appearance, and themes

We'll keep three responsibilities in view:

| Responsibility | Where it belongs in our example |
| --- | --- |
| Grid and responsive spans | `PageLayout.jsx` and the wrappers in `App.jsx` |
| Shared card appearance | `Card.jsx` |
| Button appearance | The existing buttons in `Details.jsx` |
| Theme selection | The outer element in `PageLayout.jsx` |

A theme gives colour roles their values. For example, `bg-base-100` uses a theme's base surface colour, while `text-base-content` uses its corresponding content colour. A fixed utility such as `bg-white` continues to mean white even when we choose a dark theme.

This is why installing a library won't automatically make every existing style respond to a theme. We'll need to decide which fixed colours to replace. DaisyUI's [colour reference](https://daisyui.com/docs/colors/) describes these roles.

#### What the library does for us

Shared classes can reduce repeated styling decisions and help components look consistent. They also give us a visual design to work within. If we need a very specific appearance, we may spend time adjusting that design.

We still need to preserve labels, headings, button semantics, and visible keyboard focus. A styled control is only one part of a usable interface.

### Code Walkthrough

The file paths below start inside `src/lesson-11/frontend`. Use the active `children` implementation in `PageLayout.jsx`; the starter also contains commented-out alternatives that we won't use.

<Steps>

1. **Check the existing layout.**

    Try viewport widths of 390px, 800px, and 1280px in DevTools. The starter should stack the cards on the narrow screen, put Filters above Results and Details at the medium width, and place all three beside each other at the large width.

    Open `App.jsx` and find the `md:col-span-*` and `lg:col-span-*` classes. Keep those wrappers and classes throughout this activity.

1. **Install DaisyUI in the frontend.**

    Stop Vite with **Ctrl+C**, then run these commands from the `frontend` directory:

    ```ps
    pnpm add -D daisyui@5
    pnpm dev
    ```

    Check `package.json`. DaisyUI should now appear in `devDependencies`. It supplies styles during the build, alongside our Tailwind tooling.

1. **Register the plugin and enable our themes.**

    In `src/index.css`, keep the Tailwind import and add the plugin block immediately after it:

    ```css title="src/index.css"
    @import "tailwindcss";
    @plugin "daisyui" {
      themes: light --default, dark, cupcake;
    }
    ```

    Keep the existing `:root` font and rendering declarations below this block, but remove its `color-scheme: light;` declaration so we aren't forcing a light colour scheme while experimenting with themes.

    We've enabled three themes and made `light` the default. The theme names we use later must be included here. Refer to the [DaisyUI Vite installation guide](https://daisyui.com/docs/install/vite/) and [theme configuration](https://daisyui.com/docs/themes/) when checking your setup.

1. **Verify the styles with an existing button.**

    In `Details.jsx`, replace the `className` on the **Open map** button:

    ```diff lang="jsx" title="src/components/Details.jsx"
      <button
        type="button"
    -   className="rounded border border-sky-600 px-3 py-2 text-sm font-semibold text-sky-700 hover:bg-sky-50"
    +   className="btn btn-primary btn-sm"
      >
        Open map
      </button>
    ```

    The button should now have DaisyUI's primary button appearance. `btn-sm` chooses a smaller size.

    If it still looks unstyled, check that you installed the dependency in `frontend`, saved `index.css`, and kept its import in `main.jsx`. Restart Vite if necessary before continuing.

1. **Apply a theme to the page.**

    Replace the active `PageLayout` function with the following. The grid classes and `children` remain in place.

    ```jsx title="src/components/layout/PageLayout.jsx"
    export default function PageLayout({ header, children }) {
      const theme = 'light';

      return (
        <div data-theme={theme} className="min-h-screen bg-base-200 text-base-content">
          <header className="border-b border-base-300 bg-base-100 px-6 py-4">
            {header}
          </header>

          <main className="mx-auto grid max-w-7xl grid-cols-1 gap-4 px-6 py-6 md:grid-cols-3">
            {children}
          </main>
        </div>
      );
    }
    ```

    We're placing `data-theme` on the React layout so it applies to that element and its descendants. It can also be placed on the document's `<html>` element when a whole-document theme is appropriate; the layout is a convenient choice for this exercise.

    Temporarily change the constant to `'dark'`. The page background and header surface should change, but the cards are still white. Notice that the cards still have `bg-white` in their own markup. Restore `'light'` while we refactor them.

1. **Update the shared card.**

    Replace the contents of `Card.jsx` with this version:

    ```jsx title="src/components/ui/Card.jsx"
    export default function Card({ title, children }) {
      return (
        <section className="card h-full border border-base-300 bg-base-100 text-base-content shadow-sm">
          <header className="border-b border-base-300 px-4 py-3">
            <h2 className="card-title text-sm">{title}</h2>
          </header>
          <div>
            {children}
          </div>
        </section>
      );
    }
    ```

    All three cards should update because they already use this shared component. Its `title` and `children` props haven't changed.

    `card` supplies the component styling, and `card-title` styles its heading. We retain `h-full`, the border, and our spacing utilities for this layout. The children already provide their own padding, so we aren't adding another padded body around them. Compare this with the examples in the [DaisyUI card reference](https://daisyui.com/components/card/).

1. **Finish the Details buttons and colours.**

    In `Details.jsx`, replace the final button container with:

    ```jsx title="src/components/Details.jsx"
    <div className="flex flex-wrap gap-2 border-t border-base-300 px-4 py-3">
      <button type="button" className="btn btn-outline btn-sm">
        Copy email
      </button>
      <button type="button" className="btn btn-primary btn-sm">
        Open map
      </button>
    </div>
    ```

    The buttons now share a size while retaining different visual treatments. `flex-wrap` lets them wrap when space is limited.

    Next, replace the following colour classes in the same file. Keep the other classes and all the text.

    | Existing class | Replacement |
    | --- | --- |
    | `text-gray-900` | `text-base-content` |
    | `text-gray-500` | `text-base-content/80` |
    | `text-gray-700` | `text-base-content` |
    | `text-gray-600` | `text-base-content/80` |

    The `/80` modifier makes the content colour partially transparent. Check that the resulting text remains readable on the selected surface.

    In `Header.jsx`, also replace `text-sky-600` with `text-primary` and `text-gray-500` with `text-base-content/80`. This lets the directory heading and tagline follow the theme.

1. **Compare the enabled themes.**

    In `PageLayout.jsx`, change the `theme` constant to `'dark'`, then `'cupcake'`, saving after each change.

    The page surfaces, card headings, Details text, and Details buttons should respond. We haven't changed their content or added React state.

    Look at Filters and Results as well. Their card shells respond, but some content still uses fixed gray, sky, or emerald colours. A theme doesn't rewrite those classes. That remaining migration is a useful next exercise; don't assume the whole page is ready for dark mode yet.

    Return the constant to `'light'` for the completed guided example.

1. **Verify what we kept.**

    Check the page at 390px, 767px, 768px, 1023px, 1024px, and 1280px. The layout should still transition at the same points as before.

    Tab through the controls. Check visible focus, readable labels, and text wrapping. Keep `type="button"` on the Details buttons so they retain their intended button semantics.

    Finally, run `pnpm build` from the frontend directory. This checks that the JSX and CSS configuration compile; it doesn't replace the browser checks.

</Steps>

### What we've accomplished

We've introduced a component library through the existing CSS setup, changed all three card shells through one React component, and simplified the Details buttons. Tailwind still controls the page layout and spacing.

Before moving on, compare the original Open map classes with `btn btn-primary btn-sm`. Which decisions did we hand to the library? Which decisions are still ours?
