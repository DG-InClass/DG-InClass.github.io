## Lecture

Custom elements let students define their own HTML tags with JavaScript. This lesson keeps the first component small: a neutral `<user-card>` that displays a profile photo, a name, and a short description.

### Custom Element Names

Custom element names must contain a hyphen, such as `<user-card>`. The hyphen prevents collisions with built-in HTML elements.

There are two broad categories:

- **Autonomous custom elements** extend `HTMLElement` and use their own tag name, such as `<user-card>`.
- **Customized built-in elements** extend an existing element, such as a custom button. Mention these conceptually, but keep the demo focused on autonomous custom elements.

### Templates and Shadow DOM

A `<template>` stores markup the browser does not render immediately. JavaScript can clone the template and place the copy inside a component.

Shadow DOM gives the component an internal DOM tree. In this lesson, students use `this.attachShadow({ mode: 'open' })`, clone the template, and append the clone to the shadow root.

### Attributes and Slots

Attributes are useful for simple string configuration, such as the avatar image path.

Slots let the page provide light-DOM content for the component to display. The demo uses:

- a named `name` slot
- a named `description` slot
- fallback text when no slotted content is provided

### Constructor Boundary

The constructor should focus on creating the component's initial internal structure. Work that depends on the element being connected to the document belongs in a later lifecycle lesson.

Useful references:

- <a href="https://developer.mozilla.org/en-US/docs/Web/API/Web_components/Using_custom_elements" target="_blank">Using Custom Elements</a>

### Define the Component

<Steps>
1. Notice that there is a `'template'` element already defined in `js/user-card.js`, and that it already has some `.innerHTML` of a style tag and an `<article>` as the main container of content we want to render.

1. Define a `UserCard` class that extends `HTMLElement`.

    ```js title="js/user-card.js"
    class UserCard extends HTMLElement {
      constructor() {
        super();
      }
    }
    ```

1. Attach an open shadow root to our `UserCard` instance (`this.`). This means that our "shadow DOM" is "open" for querying elements inside our component.

    ```diff lang="js" title="js/user-card.js"
      class UserCard extends HTMLElement {
        constructor() {
          super();
    +     const shadow = this.attachShadow({ mode: 'open' });
        }
      }
    ```

1. Clone the template and append it to the shadow root of our component.

    ```diff lang="js" title="js/user-card.js"
    -     const shadow = this.attachShadow({ mode: 'open' });
    +     const content = template.content.cloneNode(true);
    +     shadow.append(content);
    ```

1. Register the element so that the browser will associate a tag name of `user-card` with our `UserCard` class. This is a critical step and is a **one-time registration**.

    ```diff lang="js" title="js/user-card.js" "'user-card'"
      class UserCard extends HTMLElement {
        constructor() {
          super();
          const shadow = this.attachShadow({ mode: 'open' });
          const content = template.content.cloneNode(true);
          shadow.append(content);
        }
      }
    + 
    + customElements.define('user-card', UserCard);
    ```

    Note that all custom elements must use **hypenated tag names**, so as to never be confused with pre-defined HTML elements/tags.

1. Take a moment to see what gets rendered in the browser. Compare what is actually in the browser's HTML with what is in the HTML of our custom element's template.

    ```html title="template of user-card.js"
    <article class="card">
      <img src="" alt="">
      <div>
        <slot name="name" class="name">Unknown user</slot>
        <slot name="description" class="description">No description provided.</slot>
      </div>
    </article>
    ```

    Named `<slot>`s from our template are identified in the hard-coded `<user-card>`'s child elements.

    ```html title="index.html" "name" "description"
    <user-card avatar="assets/avatars/clarence-james.jpg">
      <span slot="name">Clarence James</span>
      <span slot="description">Enjoys helping teams turn rough ideas into clear, working prototypes.</span>
    </user-card>
    ```

    In the browser's dev tools, you can turn on the ability to view the shadow dom (see <a href="https://devtoolstips.org/tips/en/inspect-user-agent-dom/" target="_blank">Inspect the user-agent DOM</a>)
</Steps>

### Use Attributes and Slots

Notice that of all the items rendered so far in the browser, we're missing the user's image. To display that, we have to get the value of the `avatar` attribute.

<Steps>
1. First, we'll get a reference to the `<img>` element in our template's content. Since every image should have an `alt` text, we'll get the name of the user from our slot.

    ```diff lang="js" title="js/user-card.js" "content.querySelector" "this.querySelector" "[slot=\"name\"]"
      class UserCard extends HTMLElement {
        constructor() {
          super();
          const shadow = this.attachShadow({ mode: 'open' });
          const content = template.content.cloneNode(true);
    +     const image = content.querySelector('img');
    +     const name = this.querySelector('[slot="name"]')?.textContent ?? 'user';
    +
          shadow.append(content);
        }
      }
    ```

    The query selector for our slot is somewhat different than you might expect. That's because we're querying the actual child elements from our HTML (via `this.`), not the template's content.

    ```html title="index.html" "name"
    <user-card avatar="assets/avatars/clarence-james.jpg">
      <span slot="name">Clarence James</span>
      <span slot="description">Enjoys helping teams turn rough ideas into clear, working prototypes.</span>
    </user-card>
    ```

1. Next, we'll read the `avatar` attribute and assign it to the internal image's `src`, with a "fallback" value of one of the images we already have. We'll also set the `alt` property.

    ```diff lang="js" title="js/user-card.js" "content.querySelector" "this.querySelector" "[slot=\"name\"]"
      class UserCard extends HTMLElement {
        constructor() {
          super();
          const shadow = this.attachShadow({ mode: 'open' });
          const content = template.content.cloneNode(true);
          const image = content.querySelector('img');
          const name = this.querySelector('[slot="name"]')?.textContent ?? 'user';
     
    +     image.src = this.getAttribute('avatar') || 'assets/avatars/avatar.png';
    +     image.alt = `Profile photo for ${name}`;
    +
          shadow.append(content);
        }
      }
    ```

1. Once again, view the results in the browser. Play with the `index.html` to see what gets displayed as you manually edit the `<user-card>`.
</Steps>

    +   return span;
    + }

1. We'll add an attribute value using `.setAttribute` to set up our image.

    ```diff lang="js" title="js/main.js"
      function createUserCard(user) {
      // TODO: Create a <user-card> element with document.createElement().
        const card = document.createElement('user-card');
      // TODO: Create slotted spans for the name and description.
        card.append(
          createSlottedText('name', user.name),
          createSlottedText('description', user.about),
        );
      // TODO: Set the avatar attribute before appending the element.
    +   card.setAttribute('avatar', user.avatar);
    +
      // TODO: Append the finished card to programmaticCards.
      }
    ```

1. 🤔 Why is the default image not replaced by our `avatar` attribute? The secret lays in the fact that the `UserCard` constructor runs at the point we called `document.createElement()`. The image's source is only set inside the constructor, and that function exited long before we went to set the card's `avatar` attribute!

    Programmatically, we have to create the element before we can add attributes. It's not just a single-step process. But why are the user's name and description populated with the correct information? That's because we used **slots** for those child elements, and the *browser* takes on full responsibility for replacing the slotted elements. 

    If that's the case, then why were the `<user-card>`s in the HTML rendered correctly? That's because in the HTML, those are **declaratively** generated, and the browser sees the `avatar` attribute at the point that it *parses* the HTML to render the page.

    <Aside type="tip" title="Declarative vs. Imperative Programming">
      If the student hasn't yet discovered the difference between **declarative** programming and **imperative** programming, this is a great time to point out the difference.

      - **Declarative** languages such as HTML are ones in which we tell the computer ***what*** we want. It's the *browser's job* to figure out *how* to achieve that.
      - **Imperative** languages such as JavaScript are ones in which we the computer ***how*** to do something. We, the software developers, tell the browser exactly what steps to take to achieve what we want.
    </Aside>

### Fixing our `UserCard`

We need to design our custom `UserCard` element in a way that the browser can *observe* when the `avatar` attribute is changed, regardless of whether the component is created declaratively in the HTML or programmatically in JavaScript. It's a two-part process.

1. Identify what attribute names the browser should "watch".
2. Set up a callback for the browser to call when the attribute is changed.

This interactivity between the browser and our custom elements is similar to the event-driven interactivity through event listeners. When the browser detects changes to the observed attributes, a callback is invoked as a **hook** which our custom element can implement.

<Steps>
1. Begin by adding a static `observedAttributes` "getter" property to the `UserCard`. This is a special property name that the browser will "look for" when the component is registered.

    ```diff lang="js" title="js/user-card.js"
      class UserCard extends HTMLElement {
        constructor() {
          super();
          const shadow = this.attachShadow({ mode: 'open' });
          const content = template.content.cloneNode(true);
          const image = content.querySelector('img');
          const name = this.querySelector('[slot="name"]')?.textContent ?? 'user';
     
          image.src = this.getAttribute('avatar') || 'assets/avatars/avatar.png';
          image.alt = `Profile photo for ${name}`;
     
          shadow.append(content);
        }
    +
    +   static get observedAttributes() {
    +     return ['avatar'];
    +   }
      }
    ```

1. Add a property to reference the image via the constructor. We'll also clean up the constructor by removing the old code that tried to modify the image and just use fallback values.

    ```diff lang="js" title="js/user-card.js"
        constructor() {
          super();
          const shadow = this.attachShadow({ mode: 'open' });
          const content = template.content.cloneNode(true);
    +     this.image = content.querySelector('img');
    +     this.image.src = 'assets/avatars/avatar.png';
    +     this.image.alt = `Profile photo for user`;
    -     const image = content.querySelector('img');
    -     const name = this.querySelector('[slot="name"]')?.textContent ?? 'user';
    -
    -     image.src = this.getAttribute('avatar') || 'assets/avatars/avatar.png';
    -     image.alt = `Profile photo for ${name}`;
     
          shadow.append(content);
        }
    ```

1. Add an `attributeChangedCallback` to process any changes to the `avatar` attribute. Again, the name `attributeChangedCallback` is a special function name that the browser will attempt to invoke when it sees changes to any of the observed attributes.

    ```diff lang="js" title="js/user-card.js"
        static get observedAttributes() {
          return ['avatar'];
        }
    +
    +   attributeChangedCallback(name, oldValue, newValue) {
    +     if(name === 'avatar' && oldValue !== newValue) {
    +       this.image.src = newValue || 'assets/avatars/avatar.png';
    +       let name = this.querySelector('[slot="name"]')?.textContent ?? 'user';
    +       this.image.alt = `Profile photo for ${name}`;
    +     }
    +   }
    ```

1. Notice how our remaining users are now appearing in the browser.
</Steps>

### Common Errors and Fixes

| Issue | Likely Cause | Fix |
| ----- | ------------ | --- |
| Component does not upgrade | `customElements.define()` is missing or the import did not run | Import `user-card.js` from `main.js` |
| Browser rejects the name | Custom element name does not contain a hyphen | Use a name such as `user-card` |
| Slot content is missing | Slot names do not match | Match `slot="name"` with `<slot name="name">` |
| Image is blank | Attribute path is wrong or read after the wrong step | Check the local `assets/avatars` path |
