1. We're going to use a string to build a report to display to the user. Let's add a subheading for our output. Append the following to your demo.

    ```js title="~/inclass/02/demo.js"
    let report = 'Community Event Planning Demo';
    report += '\n-----------------------------';


    console.log(report);
    ```

    There's a little **escape character** in our string - `\n` - which produces a *newline* (or "blank" line) in our output. The terminal output should look like the following.

    ```ps title="Output"
    Lesson 02 demo.js has loaded
    =============================

    Community Event Planning Demo

    -----------------------------
    ```

    <Aside type="note" title="Variables">
      In all the code we've types so far, only one item is a **keyword** that's built into JavaScript. That's the `let` keyword, and its sole purpose is to tell the computer that we are *declaring* or *identifying* a **variable** in our program. Think of a variable as simple some container that we use to hold some information. Another term for a variable is to call it an **Identifier**. It's just a name that we give to our container so that we can track some bit of information that's important to our program. In this case, the `report` variable/identifier is holding textual information that we display in the console window.
    </Aside>

1. We'll plan for a games night to be held in the Learning Commons. Add some more variables and use them to build more report details.

    ```diff lang="js" title="~/inclass/02/demo.js"
      console.log('Lesson 02 demo.js has loaded');
      console.log('=============================');
      console.log();
      
      let report = 'Community Event Planning Demo';
      report += '\n-----------------------------';
      
    + let eventName = 'Neighbourhood Game Night';
    + let roomName = 'Learning Commons';
    + let guestCount = 18;
    + 
    + report += `\nEvent: ${eventName}`;
    + report += `\nRoom: ${roomName}`;
    + report += `\nExpected guests: ${guestCount}`;
      
      console.log(report);
    ```

    <Aside type="note" title="Assignment Operators">
      You probably noticed the `=` and the `+=`. Both of these are called **Assignment Operators**, and their primary job is to *store* information from the right-hand side of the operator into the variable on the left-hand side of the operator. The difference with the `+=` assignment operator is that it *adds* the value from the right-hand side to the value inside the variable. In the case of our `report` variable, we're *appending** some text to the existing value inside that variable.
    </Aside>

    <Aside type="note" title="Template Literals">
      When we add to the `report`, we're using **template literals** (also known as *template strings*). These literal strings start and end with a backtick character and can include **placeholders** for variables or expressions.
    </Aside>

1. (📍 `totalBudget`) What are games without food? Food costs money, so we'll need to do some math. We'll estimate some costs per attendee.

    ```diff lang="js" title="~/inclass/02/demo.js"
      // keep the code above, and add the following...

    + let drinkCost = 1.5;

    + let snackBudget = guestCount * snackCost;
    + let drinkBudget = guestCount * drinkCost;
    + let totalBudget = snackBudget + drinkBudget + suppliesFee;
    ```

    ```ps
    Drink budget: $
    Supplies fee: $
    Total budget: $
    ```

    Did you notice the output showed the numbers without all the correct decimal places for the money values? That's because the type of data in the `snackBudget`, `drinkBudget`, `suppliesFee`, and `totalBudget` is **numeric information**.

    ```diff lang="js" title="~/inclass/02/demo.js"
    - report += `\nSnack budget: $${snackBudget}`;

    - report += `\nDrink budget: $${drinkBudget}`;
    ```

    To you see that `.toFixed(2)` after each number variables? We use that to convert the number to a string with a fixed number of digits after the decimal point.

1. We're getting into some significant distinctions between *data types* and the operations we're trying to perform. We use *numbers* for math operations, but *strings* for assembling text.

    ```diff lang="js" title="~/inclass/02/demo.js"
      // keep the code above, and add the following...
      
    + let signUpText = '18';
    + let extraGuestText = '4';
    + let signUpCount = parseInt(signUpText);
    + let extraGuestCount = parseInt(extraGuestText);
    + let finalGuestCount = signUpCount + extraGuestCount;
    + 
    + report += '\n';
    + report += `\nThe value ${signUpText} is a ${typeof signUpText}.`;
    + report += `\nAfter parseInt(), ${signUpCount} is a ${typeof signUpCount}.`;
    + report += `\nFinal guest count: ${finalGuestCount}`;
            
      console.log(report);
    ```

    Notice the use of `parseInt()`. We use that built-in function to convert a string to a whole number. It only works if the string is comprised of *digits* (though there's a small caveate we'll address later on).

    <Aside type="note" title="About Functions and Methods">
      Something we haven't dwelt upon is the whole idea of **functions**, even though we've been using them from the start. Those places where we've used `log()`, `toFixed()` and `parseInt()`? Those are ***function calls*** where we "hand off" some value or information to get some "processing" done with that information.

      The `log()` function is a **method** that belongs to the `console` object. The job of that function is to display text on the screen (which is also referred to as a *console* - a place where we only show text).

      The `toFixed()` function is a *method* that belongs to all Number variables. That is, if the variable's data type is `'number'`, then it automatically will have a `.toFixed()` method.

      When we look at `parseInt()`, it's a little different. This function is a **global function**, meaning it's not "part of" any particular object or variable.

      Also notice that when we call the `.tofixed()` or `parseInt()`, we always get something from those function calls. That is, those functions *do something* with the information we give it and then *return* some value that we either display, drop into a template string's placeholder, or assign to a variable.

      Functions are everywhere in JavaScript, and in the not-to-distant future, we're going to be creating our own functions as we learn more about how they work and how to make our own.
    </Aside>

1. (📍 `donationText`, `donationAmount`) Let's see if we can recover some of our estimated costs by having participants donate to the games night. Insert the following before the final `console.log(report);`:

    ```diff lang="js" title="~/inclass/02/demo.js"
      
    + let donationText = '25.50';
    + let donationAmount = parseFloat(donationText);
    + 
    + report += '\n';
    + report += `\nA donation entered as '${donationText}' becomes ${donationAmount}.`;
    + report += `\nDonation type after parseFloat(): ${typeof donationAmount}`;
    + 
    + let numberExample = 7;
    + let stringExample = '7';
    + 
    + report += '\n';
    + report += `\n7 + '7' produces ${numberExample + stringExample}.`;
    + report += `\n7 * '7' produces ${numberExample * stringExample}.`;
    + report += `\n7 + parseInt('7') produces ${numberExample + parseInt(stringExample)}.`;
      
      console.log(report);
    ```

    This time, we used the `parseFloat()` to convert a string of digits into a numeric data type with a fractional or decimal portion to the value.

    <Aside type="tip" title="JavaScript is Dynamically Typed">
      JavaScript is a **dynamically typed** programming language. That means the data type of our variables in JavaScript depends *entirely* upon the **value** stored in that variable.
    </Aside>

1. Which should you choose? `parseInt()` or `parseFloat()`. It all depends on whether or not you want/need a whole number from the string of digits.
