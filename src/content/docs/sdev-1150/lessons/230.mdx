## Lecture

This lesson moves `<user-card>` from a mostly static component to a stateful component. The page passes rich user data as a property, the component manages followed state internally, and the component emits a custom event when that state changes.

### Constructor Versus Lifecycle

The constructor creates the shadow root and stores internal element references. Work that depends on the element being in the document belongs in `connectedCallback()`.

Use lifecycle callbacks for these responsibilities:

- `connectedCallback()` attaches listeners and performs initial render work.
- `disconnectedCallback()` removes listeners or cleans up resources.
- `attributeChangedCallback()` synchronizes observed attribute changes with component state.

### State, Properties, and Methods

Attributes are strings. Properties can hold richer JavaScript values, such as the `user` object in this demo.

The component exposes:

- a `user` setter and getter
- a read-only `followed` getter
- `follow()` and `unfollow()` methods
- internal followed state

### Custom Events

When followed state changes, the component dispatches `follow-change`. The event includes `detail` data and uses `bubbles: true` and `composed: true` so the containing page can listen outside the shadow boundary.

Useful references:

- https://developer.mozilla.org/en-US/docs/Web/API/Web_components/Using_custom_elements
- https://developer.mozilla.org/en-US/docs/Web/API/CustomEvent/CustomEvent
- https://developer.mozilla.org/en-US/docs/Web/API/Event/composed

### Common Errors and Fixes

| Issue | Likely Cause | Fix |
| ----- | ------------ | --- |
| Button listener runs twice | Listener added repeatedly without cleanup | Add in `connectedCallback()` and remove in `disconnectedCallback()` |
| Property data does not render | Setter stores data but does not call render | Call `render()` after setting `user` |
| Event does not reach page listener | Event does not bubble or cross shadow boundary | Use `bubbles: true` and `composed: true` |
| State and CSS disagree | Attribute and internal state are updated separately | Centralize updates in one state method |
