## Lecture

Why look at objects? The answer is simple: Because they are ***EVERYWHERE***!

You can't escape the presence of objects in JavaScript. Did you know that the `console` is an object?! 😱 The same is true for arrays and for `Math`. Don't believe me? Try seeing the result of `typeof console` or `typeof Math`, and you'll get a result of `'object'`.

Objects are *not* scary or difficult. In fact, they are pretty easy to describe. An object is a set of *properties* (to hold related information) and *methods* (to perform some behaviours).

```js title="any demo file"
let person = { name: 'Stew Dent', age: 23 }
console.log(typeof person);     // it's data type
console.log(person.name);       // one of its properties
console.log(person.valueOf());  // a method
```

<Aside type="tip" title="The Object Prototype">
Did you notice the `.valueOf()` method? Where did *that* come from?

Every object is ultimately founded upon something called the **Object Prototype**. We *could* get into all the nitty-gritty details behind why, but we'll leave that for a future discussion.

The first big takeaway is that an object can have *zero or more* properties and *zero or more* methods. The second big takeaway is there are essentially *three ways* to create/design objects. We'll introduce all three in the demo walkthrough.
</Aside>

### Constructor Function

A constructor function gives us a reusable way to create objects with the same property names. This is older JavaScript syntax, but it helps explain what class syntax is doing for us later.

<Steps>
1. (📍 `SupplyItem`) Add a constructor function for supply items. (Add a `console.clear()` to remove prior output.)

    ```diff lang="js" title="~/inclass/06/demo.js"
      describeObject(scissors);
    +
    + console.clear();
    + displayHeading("Constructor function");
    +
    + /**
    + * A SupplyItem represents some consumable item in our workshop.
    + * @param {string} name Item name
    + * @param {number} quantity The amount of items in stock
    + * @param {string} unit The per-unit quantity
    + */
    + function SupplyItem(name, quantity, unit) {
    +   this.name = name;
    +   this.quantity = quantity;
    +   this.unit = unit;
    + }
    ```

    Inside the constructor, `this` refers to the new object being created.

    <Aside type="note" title="The this Keyword">
      `this` is one of the more important JavaScript keywords students will meet.

      In this constructor function, `this.name = name` means "put a `name` property on the new object, and store the `name` argument in it."

      The meaning of `this` can change depending on how a function is called. For today, keep the focus on constructor functions and methods.
    </Aside>

1. (📍 `maskingTape`) Use the `new` keyword to create two supply items.

    ```diff lang="js" title="~/inclass/06/demo.js"
      function SupplyItem(name, quantity, unit) {
        this.name = name;
        this.quantity = quantity;
        this.unit = unit;
      }
    +
    + let maskingTape = new SupplyItem('masking tape', 6, 'rolls');
    + let glueSticks = new SupplyItem('glue sticks', 24, 'sticks');
    + describeObject(maskingTape);
    + describeObject(glueSticks);
    ```

    The `new` keyword creates a new object and calls the constructor function to initialize it.

    <Aside type="note" title="Constructor Naming">
      Constructor functions are usually named with an initial capital letter, such as `SupplyItem`.

      JavaScript does not require that capital letter, but it is a strong convention that tells readers "this function is meant to be used with `new`."
    </Aside>

    Notice that `maskingTape` and `glueSticks` are separate objects, but they were created with the same constructor.

1. Just as with object literals, we can add new properties or functions to existing objects. But if we had used object literals, we would need to add those new properties/functions one-by-one. But since we have *Constructor Function*, we have effectively defined a **prototype** for creating `SupplyItem` objects.
1. (📍 `SupplyItem`) Let's add a `use()` function to all our supply item objects. This will automatically update the quantity on hand of that supply item as people use them in their hobby projects.

    ```diff lang="js" title="~/inclass/06/demo.js"
      describeObject(glueSticks);
    + SupplyItem.prototype.use = function (amount) {
    +   this.quantity = this.quantity - amount;
    + };
    ```

1. (📍 `maskingTape`) With this in place, all our `SupplyItem` instances will now have the `use()` function.

    ```diff lang="js" title="~/inclass/06/demo.js"
      SupplyItem.prototype.use = function (amount) {
        this.quantity = this.quantity - amount;
      };
    +
    + maskingTape.use(2);
    +
    + console.log(`${maskingTape.name} remaining: ${maskingTape.quantity} ${maskingTape.unit}`);
    + 
    + glueSticks.use(3);
    + console.log(`${glueSticks.name} remaining: ${glueSticks.quantity} ${glueSticks.unit}`);
    +
    + describeObject(makingTape);
    + describeObject(glueSticks);
    ```

1. There is one drawback to using Constructor Functions. The developer must always remember to use the `new` keyword when calling/invoking constructor functions.

    Try the following code.

    ```diff lang="js" title="~/inclass/06/demo.js"
      describeObject(glueSticks);
    + 
    + let cardstock = SupplyItem("cardstock", 50, "sheet");
    ```

    Everything seems like it's working. No errors are reported. But watch what happens if we try to describe the object. Head's up! It will crash (but not in the place you might think it will)!

    ```diff lang="js" title="~/inclass/06/demo.js"
      let cardstock = SupplyItem("cardstock", 50, "sheet");
    + describeObject(cardstock);
    ```


1. Remember to use the `new` keyword with constructor functions. Let's fix the code.

    ```diff lang="js" title="~/inclass/06/demo.js" "new"
      describeObject(glueSticks);
    - let cardstock = SupplyItem("cardstock", 50, "sheet");
    + let cardstock = new SupplyItem("cardstock", 50, "sheet");
    + //              \_/  Developer must remember to use the new keyword
      describeObject(cardstock);
    ```

### Classes in JavaScript

Classes offer an alternative to constructor functions. Among the benefits, a huge advantage is the fact that you will always get a direct error message if you forget the `new` keyword. (This is a lot nicer than just having it break farther down the line.)

<Aside type="tip" title="Why are we learning classes now?">
    Why are we learning classes?
        - Classes are the foundation upon which objects are built in JavaScript.
        - We are almost always using objects in one way or another.
        - We need to dispel any notions of "magic" around what objects are.
        - When we introduce HTML, students will immediately be exposed to the Document OBJECT Model
        - Classes are not hard
            - they are essentially an alternate to constructor functions
            - they provide the benefit of requiring the `new` keyword for code to compile
    What is covered:
        - constructor
        - methods
    What are we NOT learning now?
        - No property declarations
        - No `get`/`set`
        - No `static`
        - No private members
</Aside>

Some of the tools/items used in this hobby workshop have to be signed out from the main office. These are often specialty items that are not available for each hobby station or table.

<Steps>
1. Let's clear our display and put up a heading about using JavaScript classes.

    ```diff lang="js" title="~/inclass/06/demo.js"
    + // C.1)
    + console.clear();
    + displayHeading("JavaScript Classes");
    ```

1. We'll dive into our first class - `CheckoutItem`. To declare a class, we use the `class` keyword. A class is a **bluepring** for creating objects. Additionally, a class definition should have a **constructor** (using the keyword `constructor`), which is simply a function that puts values in new object's properties; it's very similar to the work of that the *constructor function* did in the last section of this tutorial.

    ```diff lang="js" title="~/inclass/06/demo.js"
      displayHeading("JavaScript Classes");
    + 
    + class CheckoutItem {
    +   constructor(assetTag, description, location) {
    +     this.assetTag = assetTag;
    +     this.description = description;
    +     this.location = location;
    +   }
    + };
    ```

    <Aside title="The job of the constructor">
      The constructor's sole job/purpose is to ensure that any newly created object has *meaningful values* for its properties/state.

      But what do we mean by "meaningful"? Basically, that will depend upon the whole purpose of the class.
    </Aside>

1. (📍 `camera`) With our class definition in place, let's create some **instances** of the class with the `new` keyword.

    ```diff lang="js" title="~/inclass/06/demo.js"
    + let camera = new CheckoutItem("EQ-1042", "DSLR Camera kit", "Media Cabinet");
    + let microphone = new CheckoutItem("EQ-1188", "USB microphone", "Media Cabinet");
    + describeObject(camera);
    + describeObject(microphone);
    ```

    Notice how creating objects based on classes looks exactly the same as how we created objects using constructor functions.
1. Let's add a bit more information to our checkout item. We need to know who is checking out the item. And, let's make a distinction between the regular/permanent storage location of the item.

    ```diff lang="js" title="~/inclass/06/demo.js"
      class CheckoutItem {
        constructor(assetTag, description, location) {
          this.assetTag = assetTag;
          this.description = description;
          this.location = location;
    +     this.checkedOutTo = null;
    +     this.storage = location;
    +   }
    + };
    ```

1. We've got a reasonable state for our objects. Now, we should have some *behaviour*. We'll do this by adding three methods to our class.

    ```diff lang="js" title="~/inclass/06/demo.js"
      class CheckoutItem {
        constructor(assetTag, description, location) {
          this.assetTag = assetTag;
          this.description = description;
          this.location = location;
          this.checkedOutTo = null;
          this.storage = location;
        }
    + 
    +   checkout(studentName, station) {
    +     this.checkedOutTo = studentName;
    +     this.location = station;
    +   }
    + 
    +   returnItem() {
    +     this.checkedOutTo = null;
    +     this.location = this.storage;
    +   }
    + 
    +   moveTo(location) {
    +     this.location = location;
    +     this.storage = location;
    +   }
      };
    ```

    Notice something interesting about classes. When we add functions/methods to our class, we don't use the `function` keyword. (We also didn't use `function` with our `constructor`.) The fact that they *are* functions is implied by their *grammar*:
    
    ```js
    functionName(parameters) {
      // body
    }
    ```

    What's key here is that this grammar *only applies within the context of a **class definition***.
1. (📍 `camera`) Now that we have the ability to call methods on our objects, let's do so.

    ```diff lang="js" title="~/inclass/06/demo.js"
    + displayHeading("Using Checkout Items", "~");
    + camera.checkout("Samira Patel", "Recording Pod 1");
    + describeObject(camera);
    + 
    + microphone.moveTo("Sound Cabinet");
    + describeObject(microphone);
    ```

</Steps>

<Aside type="note" title="What is a Class?">
A **class* is a *blueprint* for creating objects. It defines
- what an object "looks like" (its *state*/*properties*), and
- how an object "behaves" (its methods/functions)
</Aside>
