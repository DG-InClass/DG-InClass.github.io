## Lecture

The previous lesson created a working `<user-card>`. This lesson focuses on the styling boundary created by Shadow DOM.

Styles inside a shadow root affect the component's internal markup. Page styles do not freely reach into the shadow root, but the containing page can still style the host element and any intentional hooks the component exposes.

### Styling Hooks

Use the following hooks deliberately:

- `:host` styles the custom element from inside its own shadow root.
- `:host()` targets the host only when it matches a selector, such as an attribute.
- `::slotted()` styles light-DOM content assigned to a slot.
- CSS custom properties let the page provide theme values to the component.
- `part` and `::part` expose specific internal elements for external styling.

### Attribute Changes

The avatar image path is still a simple attribute. To respond when it changes after the element is created, the component needs:

```js
static get observedAttributes() {
  return ['avatar'];
}
```

and:

```js
attributeChangedCallback(name, oldValue, newValue) {
  // update rendered state
}
```

Useful references:

- https://developer.mozilla.org/en-US/docs/Web/API/Web_components/Using_shadow_DOM
- https://developer.mozilla.org/en-US/docs/Web/API/Web_components/Using_custom_elements
- https://developer.mozilla.org/en-US/docs/Web/CSS/::part
- https://developer.mozilla.org/en-US/docs/Web/CSS/::slotted

### Style Host Variants, Slotted Content, and `::part` Pseudo-Elements

There are other ways we can expose the internals of our custom element to the styling preferences of our host. These are through the `::slotted` and `::part` pseudo-elements.

- The `::slotted` pseudo-elements are CSS styles we add to the inside of our custom element
- The <a href="https://developer.mozilla.org/en-US/docs/Web/CSS/Reference/Selectors/::part" target="_blank">::part` pseudo-element`</a> is styled in the host, but linked up to the children of our custom element through the <a href="https://developer.mozilla.org/en-US/docs/Web/HTML/Reference/Global_attributes/part" target="_blank">`part` attribute</a>.

<Steps>
1. We'll also add a custom "variant" attribute that the host can access to apply custom styles.

    ```diff lang="css" title="js/user-card.js"
          :host {
            --card-bg: var(--user-card-bg, #ffffff);
            --card-color: var(--user-card-color, #172033);
            --card-accent: var(--user-card-accent, #0f766e);
            display: block;
          }
     
    -     /* TODO: Use :host([variant="featured"]) for a featured card style. */
    +     :host([variant="featured"]) .card {
    +       border-color: var(--card-accent);
    +     }
    ```

1. We'll style assigned slot content with `::slotted()` styles.

    ```diff lang="css" title="js/user-card.js"
          img {
            width: 72px;
            height: 72px;
            border-radius: 50%;
            object-fit: cover;
          }

    +     ::slotted([slot="name"]) {
    +       display: block;
    +       color: var(--card-accent);
    +       font-weight: 700;
    +     }

    +     ::slotted([slot="description"]) {
    +       display: block;
    +       margin-top: 0.25rem;
    +       color: var(--card-muted);
    +       line-height: 1.4;
    +     }

    ```

1. Ask students to identify which parts of `css/styles.css` from the host are being applied to the custom element when we toggle the theme.
1. We'll add a `part` attribute to the `<img>` element of our template. This makes our image shadow DOM element "visible" to the parent DOM, allowing us to apply CSS styles based on the `::part` pseudo-element.

    ```diff lang="html" title="js/user-card.js" "part="
        </style>

        <article class="card" part="card">
    -     <img src="" alt="">
    +     <img part="avatar" src="" alt="">
          <div>
            <slot name="name">Unknown user</slot>
            <slot name="description">No description provided.</slot>
          </div>
        </article>
    ```

1. Now, we can modify our `css/styles.css` to include an outline to our avatar image. 

    ```diff lang="css" title="css/styles.css"
      user-card {
        --user-card-bg: var(--surface);
        --user-card-color: var(--text);
        --user-card-muted: var(--muted);
        --user-card-accent: var(--accent);
      }
    + 
    + user-card::part(avatar) {
    +   outline: 3px solid color-mix(in srgb, var(--accent), white 40%);
    + }
    ```

</Steps>

### Respond to Attribute Changes

Remember how we added the `observedAttributes` property and the `attributeChangedCallback()` function to our custom element? We'll leverage that by programmatically changing the avatar image as the user clicks on a card.

<Steps>
1. Change the avatar attribute from a event listener in `main.js` when the demo card is clicked.

    ```diff lang="js" title="js/main.js"
      avatarDemo.addEventListener('click', () => {
    -   // TODO: Change the avatar attribute to another local avatar path.
        avatarIndex = (avatarIndex + 1) % users.length;
    +   avatarDemo.setAttribute('avatar', users[avatarIndex].avatar);
      });
    ```

1. Watch the effect in the browser. Confirm the internal image updates without recreating the whole card.
</Steps>

### Common Errors and Fixes

| Issue | Likely Cause | Fix |
| ----- | ------------ | --- |
| Page CSS does not style internal markup | Shadow DOM encapsulation is working | Expose a CSS custom property or `part` |
| Slotted name style does not apply | Selector is targeting internal text instead of assigned light DOM | Use `::slotted([slot="name"])` |
| Host variant does not apply | Attribute selector is written for an internal element | Use `:host([variant="featured"])` |
| Avatar does not update | Attribute is not observed | Add `avatar` to `observedAttributes` |
